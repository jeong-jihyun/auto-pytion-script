# 114 주문 한도 사후 점검

## 무엇을 하나요?
하루 주문 내역을 시간순으로 다시 따라가며 **1회 주문 한도, 계좌 일 누적 한도, 계좌·종목 일 누적 한도, 기준가 대비 가격 괴리율**을 넘은 주문을 찾습니다. 한도는 JSON 파일로 바꿀 수 있습니다.

## 어떤 업무에 쓰나요?
- 증권·선물 주문 시스템의 한도 체크가 제대로 동작했는지 장 마감 후 확인 (준법·리스크 점검)
- 한도 설정 변경 전, 과거 주문으로 "이 한도면 몇 건이 걸리나" 시뮬레이션

## 설치
파이썬 3.8 이상. 설치할 것 없음.

## 실행 예시
```
python3 main.py sample/orders.csv sample/limits.json -o output/limit_violations.csv
```

## 입력 / 출력 예시
- 주문 CSV 열: `주문번호, 시각, 계좌, 종목, 매매구분, 수량, 가격, 기준가(선택)`
- 한도 JSON: `1회주문한도, 계좌일누적한도, 종목일누적한도, 가격괴리율(%)` — 0이거나 없으면 그 항목은 점검 안 함
- 출력 CSV 열: `주문번호, 시각, 계좌, 종목, 매매구분, 주문금액, 위반유형, 실제값, 한도`

샘플 결과: 4건. O-0004(1,800만 원)는 1회 한도 1,500만 원 초과, O-0005는 기준가 대비 14.41% 괴리, O-0006에서 ACC-01 계좌 누적(4,975만 원)과 가상전자 누적(3,175만 원)이 한도를 넘습니다.

## 주의사항
- 매수·매도를 구분하지 않고 금액을 모두 더합니다(보수적 점검). 회사 기준이 다르면 CSV를 먼저 나눠 돌리세요.
- 시각은 같은 날짜 안의 `HH:MM:SS` 문자열 정렬을 기준으로 합니다. 정정·취소 주문은 반영하지 않습니다. 샘플 종목·계좌는 가짜입니다.
