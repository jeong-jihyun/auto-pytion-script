# 189 로그 해시 체인 (위변조 확인)

## 무엇을 하나요?
로그 파일의 **줄마다 해시를 사슬처럼 이어** 체인 파일(CSV)에 기록해 둡니다. 나중에 같은 로그를 검사하면
- 모두 같으면 → 정상
- 뒤에 새 줄만 쌓였으면 → 정상(새로 쌓인 줄 수 알려 줌)
- 중간이 고쳐졌으면 → **처음 달라진 줄 번호와 그 줄 내용**
- 끝부분이 지워졌으면 → 사라진 줄 수

를 알려 줍니다.

## 어떤 업무에 쓰나요?
- 접근 로그·권한 변경 로그·개인정보 조회 로그의 무결성 증적
- 감사·보안 점검 때 "로그가 고쳐지지 않았음"을 보여 주기
- 일 마감 때 그날 로그의 체인을 남겨 두기

## 생각의 흐름
- 파일 전체 해시 하나만 두면 "바뀌었다"만 알 수 있고 **어디가** 바뀌었는지 모릅니다.
- 줄마다 `h(n) = SHA-256(h(n-1) + n번째 줄)` 로 이어 붙이면, 한 줄이 바뀔 때 그 줄부터 뒤가 모두 달라집니다. 그래서 **처음 달라진 줄**이 고쳐진 곳입니다.
- 로그는 계속 쌓이므로 "기록 뒤에 추가된 줄"은 위변조로 보지 않습니다.

## 설치
파이썬 3.8 이상. 추가 설치 없음.

## 실행 예시
```bash
# 1) 기록 (sample 에는 이미 만들어 둔 체인 파일이 있습니다)
python main.py make sample/access.log --chain output/access.chain.csv
# 2) 검사
python main.py verify sample/access.log --chain sample/access.log.chain.csv
python main.py verify sample/access_tampered.log --chain sample/access.log.chain.csv
```
종료 코드: 정상 0, 위변조 의심 2. 스케줄러에서 알림 조건으로 쓸 수 있습니다.

## 입력 예시
`sample/access.log` (가짜 접근 로그), `sample/access_tampered.log` (5번째 줄의 `rows=120` 을 `rows=12` 로 고친 사본)

## 출력 예시
```
검사: sample/access_tampered.log (기록 6줄 / 현재 6줄)
[위변조 의심] 5번째 줄부터 내용이 기록과 다릅니다(그 줄이 고쳐졌거나, 그 앞에 줄이 끼워지거나 빠졌습니다).
  현재 5번째 줄: 2026-11-12 09:10:33 INFO  user=u2002 action=EXPORT target=고객목록 rows=12
```
```
검사: output/grow.log (기록 6줄 / 현재 7줄)
[정상] 기록한 6줄은 그대로이고, 그 뒤에 1줄이 새로 쌓였습니다.
```

## 주의사항
- **체인 파일은 로그와 다른 곳**(다른 서버, 읽기 전용 저장소, 메일 보관 등)에 두어야 의미가 있습니다. 같은 사람이 로그와 체인을 함께 고칠 수 있으면 막지 못합니다. 더 강하게 하려면 마지막 해시 값을 결재 문서나 별도 시스템에 남기세요.
- 로그 회전(`app.log` → `app.log.1`)으로 파일이 바뀌면 새 파일에 대해 다시 `make` 하세요.
- 줄 끝 문자(CRLF/LF)는 무시하므로 윈도우·리눅스 간 복사로 인한 차이는 위변조로 보지 않습니다.
- 기존 체인 파일은 `--overwrite` 없이는 덮어쓰지 않습니다.
