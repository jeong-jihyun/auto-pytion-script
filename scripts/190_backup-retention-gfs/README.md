# 190 GFS 규칙으로 백업 보관 정리

## 무엇을 하나요?
백업 파일을 **일 7개 · 주 4개 · 월 12개**(GFS: 할아버지-아버지-아들) 규칙으로 남기고, 나머지를 **정리 후보**로 고릅니다. 기본은 미리보기이고, `--apply` 를 줘도 **지우지 않고** 휴지통 폴더로 옮기기만 합니다.

## 어떤 업무에 쓰나요?
- 매일 쌓이는 DB·파일 백업으로 디스크가 찰 때
- "최근 N개만 남기기"로는 한 달 전·반년 전 자료가 없어서 곤란할 때
- 백업 보관 정책(예: 일 7, 주 4, 월 12)을 문서로 정해 두고 지키는지 확인할 때

## 생각의 흐름
1. 날짜는 **파일 이름**에서 읽습니다(`db_20261113.zip`, `db_2026-11-13_0200.zip`). 수정 시각은 복사하면 바뀌어서 믿지 않습니다.
2. 남기는 규칙
   - 일: 최근 백업 날짜 7일치(하루에 여러 개면 그날 마지막 것)
   - 주: 최근 4주 각각의 마지막 백업
   - 월: 최근 12개월 각각의 마지막 백업
3. 한 파일이 여러 규칙에 걸리면 한 번만 남기고 이유를 `(일/주/월)` 로 모두 적습니다.
4. 이름에서 날짜를 못 읽은 파일(예: 수동 백업)은 **건드리지 않습니다**.

## 설치
파이썬 3.8 이상. 추가 설치 없음.

## 실행 예시
```bash
# 연습: 파일 이름 목록으로 시뮬레이션 (아무것도 옮기지 않음)
python main.py --list-file sample/backup_list.txt --pattern .zip
# 실제 폴더 미리보기
python main.py --folder D:/backup/erp --pattern .zip
# 실제로 옮기기(삭제 아님) - 폴더 안 retention_trash 로
python main.py --folder D:/backup/erp --pattern .zip --apply
# 규칙 바꾸기
python main.py --folder D:/backup/erp --days 14 --weeks 8 --months 24
```

## 입력 예시 (`sample/backup_list.txt`)
```
erp_db_20261113_0200.zip
erp_db_20261113_1530.zip
erp_db_20261112_0200.zip
...
erp_db_2025-12-31.zip
erp_db_manual_before_patch.zip
```

## 출력 예시
```
대상 104개 → 남김 14개, 정리 후보 89개, 날짜 못 읽음 1개
규칙: 일 7 · 주 4 · 월 12

[남김]
  2026-11-13  erp_db_20261113_1530.zip  (일/주/월)
  2026-11-12  erp_db_20261112_0200.zip  (일)
  2026-11-08  erp_db_20261108_0200.zip  (일/주)
  2026-11-01  erp_db_20261101_0200.zip  (주)
  2026-10-31  erp_db_20261031_0200.zip  (월)
  ...
[정리 후보]
  2026-11-13  erp_db_20261113_0200.zip
  2026-11-06  erp_db_20261106_0200.zip
  ...
[날짜 못 읽음 - 건드리지 않음]
  erp_db_manual_before_patch.zip
```

## 주의사항
- 주는 ISO 기준(월요일 시작)입니다.
- 같은 날 여러 파일이면 **이름순으로 가장 뒤** 것을 그날의 마지막으로 봅니다. 시각을 `_0200`, `_1530` 처럼 이름에 붙여 주세요.
- 실제 삭제는 하지 않습니다. 휴지통 폴더를 확인한 뒤 사람이 직접 지우세요. 휴지통에 같은 이름이 있으면 건너뜁니다.
- 백업이 정말 열리는지는 따로 확인하세요(SQLite는 183번, zip은 034번 체크섬 참고).
